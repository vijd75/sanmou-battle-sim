# 三国谋定天下战斗模拟与机制校准

这是一个面向《三国：谋定天下》的本地战斗模拟与战报分析项目。它将队伍配置、结构化武将与战法数据、逐事件结算、详细战报和实测校准流程放在同一套工具中，便于观察战斗过程、复现实验条件，并逐项检查机制与数值。

项目不是官方客户端，也不宣称完整复刻全部游戏规则。机制实现和数值可信度分别维护：某项效果已能运行，不代表它的触发条件、目标选择、概率或属性系数都已由游戏数据确认。具体状态见文末的校准资料。

## 当前功能

- 配置双方队伍：每队 3 名武将，可设置阵型、等级、兵力、自由属性和携带战法；武将与战法选择支持检索。
- 在浏览器中运行模拟并查看战斗结果、双方战损、武将兵力、战法统计和逐条详细战报。
- 详细战报按布阵和实际战斗回合分段，可用侧边导航跳转；点击日志中的武将名可查看该时刻的属性、兵力、增减伤和状态快照。
- 点击已携带战法可在战法旁查看满级原始描述。
- 支持可复现随机结果（随机种子）、命令行模拟，以及 Python 引擎的连续平局战斗模式。
- 结构化数据包含 102 名武将和 233 个战法。引擎已实现伤害、治疗、状态、属性变化、概率触发和多目标结算等通用路径；单个战法的实现与验证程度并不相同，需结合审计和校准记录判断。
- 提供独立的演武大会助手：记录初始卡池、六轮选秀、支援位与锦囊结果，并根据当前已选卡牌规划三支队伍；支持选秀中途录入、跳过未记录轮次和随时查看阶段性建议。
- 演武构筑顾问可连接用户配置的 OpenAI 兼容模型，结合 102 名武将、233 个战法资料及带来源标注的体系知识，分析核心协同、候选价值、替代路线与跨队机会成本。资料只在用户主动发送咨询时发往所配置的服务；视频经验不作为实测胜率。

## 模拟流程

每场战斗由两支三人队伍组成。模拟器先读取队伍、武将、阵型和战法配置，再按战斗阶段推进效果：

1. **布阵阶段**：处理已配置的队伍与战前效果，并记录战前状态。
2. **行动顺序**：根据当前先攻和行动顺序规则，为本回合确定行动次序。
3. **武将行动**：执行行动开始效果、被动/指挥联动、主动战法、普通攻击、反击和追击等事件。
4. **逐目标结算**：多目标效果逐个完成；前一目标引发的属性、兵力或状态变化可以影响后续目标的计算和联动触发。
5. **回合收尾**：处理回合结束效果、持续时间和状态更新；达到胜负条件或回合上限时结束战斗。

每条战报记录尽可能对应结算事件，并保存该时刻相关武将的状态快照。这样可以把“为什么触发、对谁生效、由谁造成伤害、结算后剩余多少兵力”与模拟状态对应起来，便于和游戏内详细战报逐行核对。

战斗核心位于 `src/sanmou_sim/`。浏览器由 `web/server.py` 提供本地 HTTP 服务，并调用 Python 模拟引擎。结构化规则分别保存在 `data/generals.json`、`data/skills.json` 和 `data/statuses.json`。

## 环境要求

- Python 3.11 或更新版本。
- 浏览器用于打开本地网页配置器。
- 可选：`pytest` 用于运行 pytest 测试；CMake 与 C++17 编译器用于构建独立 C++ 程序。

## 启动网页配置器

在项目根目录运行：

```powershell
python web\server.py
```

默认打开 <http://127.0.0.1:8000/web/index.html>。若端口被占用，可指定其他端口：

```powershell
python web\server.py --port 8001
```

停止服务时在终端按 `Ctrl+C`。本地服务同时提供静态网页和 `/api/simulate` 模拟接口。

## 演武大会助手

启动同一服务后打开 <http://127.0.0.1:8000/web/arena.html>。助手可在初始卡池、选秀进行中或队伍编成阶段接入，不要求补记已错过的候选组；初始发放为 4 名武将和 8 个战法，六轮依次选择武将、战法、战法、武将、战法、战法。每轮可记录三组候选，也可直接录入游戏里已经选择的结果。

支援位和锦囊分别登记，编成建议使用当前已记录的卡池，并允许手动调整队伍、战法和阵型。选秀状态保存在当前浏览器本地。顾问侧栏使用用户配置的兼容模型接口；不配置接口时，选秀记录和基础编成功能仍可使用。

顾问上下文包含原始 102 名武将与 233 个战法的名称目录，并按当前卡池、选秀候选和对话提及动态附加完整卡牌资料。`data/arena_team_systems.json` 收录来源可追溯的视频体系先验；其作者评级、统计口径和赛季结论均非独立胜率验证。每次发送咨询时，当前卡池和相关资料会发送到用户配置的模型服务。

## 命令行模拟

无需安装即可从源码运行：

```powershell
$env:PYTHONPATH = "src"
$env:PYTHONIOENCODING = "utf-8"
python -m sanmou_sim examples/sample_battle.json --seed 7
```

`--seed` 用于固定随机序列。Python 引擎也支持连续平局战斗：

```powershell
python -m sanmou_sim examples/sample_battle.json --seed 7 --campaign --max-battles 8
```

若希望安装项目及命令行入口，可在支持 `pip` 的 Python 环境中执行：

```powershell
python -m pip install -e .
sanmou-sim examples/sample_battle.json --seed 7
```

## 测试与审计

推荐先运行基础验证：

```powershell
$env:PYTHONPATH = "src"
python -m compileall -q src tests web
python tests/smoke_test.py
python tests/rules_regression.py
```

可选安装 pytest 后运行测试集：

```powershell
python -m pytest
```

演武顾问接口和卡牌目录测试：

```powershell
python -m pytest tests/test_arena_advisor_api.py -q
```

项目另有全库战法效果和目标顺序审计：

```powershell
python tests/audit_skill_effects.py
python tests/full_skill_sequence_audit.py
python tests/target_sequence_audit.py
```

审计用于发现未映射效果、执行异常和结算顺序回归；它不能证明未经过游戏数据校准的系数、概率或特殊机制正确。

回归测试适合在修改伤害乘区、减伤、状态时长、目标选择或触发顺序后运行。战报样本分析脚本位于 `reports/`，通常先清洗游戏战报、整理每次事件的属性与增减伤快照，再对候选公式进行拟合和回代。新公式应保留原始样本、适用条件、误差和未覆盖场景，并经过针对性回归后再接入模拟器。

## SQLite 战报库

战报分析数据可用 Python 自带的 SQLite 整理，无需安装或启动数据库服务。导入器默认读取采集目录中的标准“全部伤害事件.csv”，并在 `data/battle_damage.sqlite` 生成本地数据库（已加入 Git 忽略）：

```powershell
python tools\damage_db.py
```

也可指定 CSV 和数据库路径：

```powershell
python tools\damage_db.py --csv "D:\path\全部伤害事件.csv" --db "D:\path\battle_damage.sqlite"
```

数据库保留逐条伤害原始 CSV 行、攻击者/目标快照、数值乘区、数据质量提示、战报来源路径，以及武将/战法/状态参考数据。兵种以标准事件 CSV 中经过校正的攻击者/目标兵种列为准；若状态 JSON 与其不同，仍保留 JSON 原文追溯，但不覆盖校正值。相同战报再次导入会替换该战报事件，不重复累计；被标记为重复的战报会保留并标注关联，不会自动丢弃。拟合公式登记表与事件数据分离，候选公式不能自动视为已确认。

## 机制与校准

实现重点是把战斗拆成可检查的事件，而不是只比较胜负结果。当前引擎处理行动顺序、战法触发、目标选择、伤害与治疗、状态持续时间、多目标依次结算和战后状态更新等环节。已接入的规则仍需按具体战法和测试覆盖范围核验。

校准以游戏内战报、武将状态快照和控制变量测试为主要依据。机制记录回答“何时触发、作用于谁、如何联动”；数值记录回答“基值、概率和属性影响是否与样本吻合”。拟合结果是对现有样本的解释或候选模型，不等同于官方公式，也不应超出样本范围外推。

涉及减伤与规避时，区分效果施加前的原始数值和目标既有状态影响后的实际增量，并对每个目标分别结算。伤害事件同时区分战法拥有者、实际伤害来源、受击目标及结算后的兵力。多目标效果按顺序更新战斗状态，以保留前一目标对后续目标的影响；未明确允许叠加的持续效果按刷新时长处理。

校准状态及证据入口：

- `CALIBRATION_TRACKER.md`：逐项记录样本、条件、候选拟合与待测机制。
- `ATTRIBUTE_COEFFICIENT_FIT_STATUS.md`：汇总属性影响系数的拟合状态。
- `SKILL_MECHANICS_AUDIT.md`：检查战法效果的结构化覆盖和实现情况。
- `DEVELOPMENT_LOG.md`：追踪实现变更、机制决策和验证过程。

## 当前边界

- 不同战法可能使用不同属性系数与伤害/治疗模型；已有拟合仅适用于其记录的战法和样本条件，不能直接视为全游戏通用规则。
- 仍有战法机制、基础值、属性系数、概率和结算边界处于部分确认或待测状态。模拟结果用于机制观察和实验对照，不应直接当作准确的竞技预测。
- 部分战前系统或角色构筑要素若尚未进入配置数据模型，就不会被模拟器自动补全；运行结果只基于当前配置和已实现效果。
- 连续战斗模式支持 Python CLI；网页主要用于单场交互配置与查看战报。
- 仓库保留 `cpp/` C++ 实现，但当前网页服务调用的是 Python 引擎；除非专门运行对应 C++ 构建与测试，不应默认两套实现行为完全一致。

## 数据与贡献

武将、战法和状态分别维护在 `data/generals.json`、`data/skills.json`、`data/statuses.json`。新增或修正机制时，请同步补充针对性回归测试，并在 `DEVELOPMENT_LOG.md` 记录数据依据、规则决策和验证结果；拟合样本及其适用条件记录在 `CALIBRATION_TRACKER.md` 或对应专题报告中。
